# Lingolog

## 실제 OpenAI 교정 (허용 사용자 개발 테스트)

`correct-diary`에 Responses API 기반 영어·일본어 교정과 한국어 설명을 구현했습니다. 실제/모의 모드를 구분하고 기존 계약·검증·원문 보존·실패 시 기존 결과 유지를 적용합니다. 실제 모드는 서버 Secrets의 사용자 allowlist를 통과해야 하며, 사용자당 하루 5개 고유 요청·동시 예약 1개와 실제 호출 하루 5번 제한을 DB에서 처리합니다. 실제 입력/출력/전체 토큰을 비공개 DB에 기록하며, 사용량을 모르는 요청은 자동 재호출하지 않습니다.

추가 패키지 설치는 없습니다. 이번 변경의 원격 배포와 유료 API 호출은 실행하지 않았습니다. API 키·모델·허용 ID 등록부터 migration/함수 재배포·실제 기기 확인까지의 PowerShell 명령은 [OpenAI 교정 설정 안내](docs/openai-correction-setup.md)에 정리했습니다. `npm run test:openai`는 유료 호출 없이 검증합니다. 아래 내용은 이전 단계의 기능 기록이며 현재 서버 모드는 `disabled` / `mock` / `model`을 지원합니다.

## Supabase 익명 인증·서버 모의 교정

제공한 개발 프로젝트의 공개 URL과 publishable key를 `.env.local` / `.env.example`로 관리합니다. 익명 세션은 영구 저장·재사용·토큰 갱신하며, 인증 실패해도 기존 로컬 기능은 유지합니다. 서버 모드는 기본 false입니다. `mock` 모드에서는 고정 영어/일본어 테스트 문장만 **모의 교정**으로 명확히 표시합니다.

`supabase/`에 사용자 JWT를 검증하는 `correct-diary` 함수와 사용자당 하루 5개 고유 요청·동시 예약 1개를 원자적으로 제한하는 SQL migration을 추가했습니다. DB/함수는 아직 원격 배포하지 않았습니다. 직접 할 대시보드 설정·PowerShell 연결/배포 명령·환경변수·변경 DB 객체·실제 기기 테스트는 [Supabase 설정·배포 안내](docs/server-correction-setup.md)를 순서대로 따라 주세요. `npm run test:supabase`는 외부 요청 없이 검증하며, 배포 후 명시적으로 `npm run verify:supabase`를 실행하면 개발 서버 인증·모의 계약을 확인합니다.

## 서버 교정 연결 준비

교정 결과를 원문 버전·학습/설명 언어·교정 시각과 함께 일기와 별도로 영구 저장합니다. 샘플/서버 공통 인터페이스, 요청 상태·중복 차단·재시도, 응답 검증과 타임아웃을 준비했습니다. 수정한 일기의 기존 결과는 **수정 전 교정**으로 표시하며 현재 원문에 잘못 연결하지 않습니다. 서버 어댑터는 기본 비활성이고 로그인 화면은 추가하지 않았습니다. 샘플 교정과 표현 저장·TTS·복습은 유지합니다. 추가 패키지는 없습니다.

Supabase에서 직접 설정할 항목, 이후 인증·요청 제한·비밀키·모델 검증 구현, 요청/응답 계약과 실제 기기 확인 순서는 [서버 교정 연결 준비 문서](docs/server-correction-setup.md)에 정리했습니다. 검증 명령은 `npm run test:correction`입니다.

## 표현 재사용 미션

작성 화면에서 해당 학습 언어의 저장 항목을 최대 두 개 제안합니다. 복습 이력이 있는 항목을 우선하며 표현·한국어 뜻·예문을 볼 수 있습니다. **다른 표현**으로 후보를 바꾸거나 **이번에는 건너뛰기**로 자유롭게 작성하세요. 항목이 없거나 단어장·복습 데이터를 불러오지 못해도 일기 저장은 가능합니다. 홈에는 새 카드나 통계를 추가하지 않았습니다.

저장 후 상세의 **표현 포함 확인**은 원문에 제안 표현이 포함되었는지만 확인합니다. 영어는 대소문자·연속 공백을 정규화하고 다른 단어의 일부가 일치한 것은 제외합니다. 일본어는 별도 문자열 포함 규칙을 사용합니다. 활용형·동의어 판정, 문법 채점, 숙달 평가와 추가 집 보상은 제공하지 않습니다. 문법 유형의 템플릿 표현도 실제 문자열이 들어간 경우에만 포함으로 확인됩니다.

`src/reuse/`에 추천·언어별 판정·저장 로직을 분리했습니다. 기록은 `@lingolog/expression-reuse/v1`에 학습 항목 ID, 일기 ID, 언어, 확인한 표현, 확인 시각, 일기 수정 버전, 현재 포함·삭제 상태를 저장합니다. 일기에는 선택한 표현 스냅샷과 `revision`을 함께 저장하므로 별도 확인 기록 저장에 실패해도 일기를 유지하고 다시 확인할 수 있습니다. 같은 일기·항목은 한 기록으로 갱신하고, 수정하면서 표현을 지우면 현재 사용 상태가 변경됩니다. 단어장 상세에서 포함된 일기로 이동하며 삭제한 일기는 현재 집계와 연결에서 제외합니다.

기존 일기는 수정 버전 0·미션 없음으로 읽으며 새 필드는 이후 저장 시 추가합니다. 과거 일기에 임의의 미션을 붙이지 않고 기존 저장 키와 일기·단어장·복습·성장 데이터를 유지합니다. 기록 읽기 실패나 손상은 원본을 덮어쓰지 않고 오류와 재시도를 제공합니다. 추가 패키지 설치는 없습니다.

실제 iPhone / Android 확인:

1. 설정에서 영어 교정용 샘플을 추가하고 교정 결과의 표현 두 개 이상을 단어장에 저장합니다. 한 항목을 복습한 뒤 새 일기 작성에서 해당 항목이 우선 제안되는지 확인합니다.
2. 예문 보기·다른 표현·건너뛰기를 확인합니다. 건너뛰거나 항목이 없어도 저장할 수 있고, 뒤로 갔다 작성 중인 글로 돌아오면 선택한 표현과 본문이 유지되어야 합니다.
3. `thankful` 제안에 `THANKFUL`을 쓰면 포함, `unthankful`만 쓰면 미확인입니다. `go for a walk`는 대소문자와 여러 공백이 달라도 포함되어야 합니다. 저장 후 짧은 안내와 단어장 상세의 일기 연결을 확인합니다.
4. 일기를 다시 저장해도 연결 수가 늘지 않아야 합니다. 표현을 지워 수정하면 연결이 사라지고, 다시 넣어 저장하면 한 번만 연결되어야 합니다.
5. 연결된 일기를 삭제하면 현재 집계·링크에서 빠지고, 저장된 학습 항목·예문·복습 기록은 유지되어야 합니다. 완전 종료·재실행 후에도 같은 상태인지 확인합니다.
6. 일본어 선택 시 영어 항목이 제안되지 않아야 합니다. 현재 일반 흐름에는 일본어 표현 추출이 없으므로 일본어 항목이 없으면 미션 없이 작성하는 것이 정상입니다. 일본어 항목이 있는 별도 테스트 환경에서는 일본어 문자열 포함과 언어별 연결을 확인합니다.
7. 작은 화면·큰 글자·키보드 열린 상태에서 예문·후보 변경·건너뛰기·저장 버튼을 스크롤해 사용할 수 있는지 확인합니다. 기존 홈·달력·TTS·집 보상 동작도 확인합니다.

`npm run test:reuse`는 언어별 판정, 추천 우선순위, 중복 방지, 수정·삭제 반영, 실패 후 재시도, 재실행 복원과 초안 유지를 검증합니다. 별도 테스트 환경에서 재사용 저장 키의 쓰기만 실패시키면 일기는 저장되고 확인 재시도 안내가 나오는지 확인할 수 있습니다.

영어부터 시작해 여러 외국어로 하루를 기록하는 Expo / React Native 앱입니다. Expo SDK 57, React 19, TypeScript와 Expo Router를 사용합니다.

## 실행

```sh
npm install
npx expo start
```

개발 서버에서 QR 코드를 SDK 57을 지원하는 Expo Go로 스캔하세요. 웹에서는 `npm run web`으로 확인할 수 있습니다. Windows PowerShell에서 스크립트 실행 정책 오류가 나면 `npm.cmd` / `npx.cmd`를 사용하세요.

## 현재 기능

- 홈: 영어/일본어 선택, 뉴욕/도쿄 집과 성장 진행, 오늘의 질문, 일기 쓰기
- 일기: 언어별 월간 달력, 월 이동·오늘 이동, 선택한 날짜의 일기 카드, 과거 날짜 작성
- 작성: 별도 화면에서 언어·일기 날짜·질문 표시, 여러 줄 입력, 작성 중인 내용 유지
- 상세: 저장한 내용 전체 표시, 수정·삭제, 삭제 확인창, 수정일 표시, 교정하기
- 교정: 샘플 교정, 원문·교정문, 문법 오류 수정·자연스러운 표현 제안, 한국어 설명, 표현별 저장
- 단어장: 저장한 단어·표현·문법의 목록·상세·삭제, 오늘 복습·이력, 기존 참고용 영어 샘플 단어 4개
- 설정: 학습 언어 영어·일본어 선택, 설명 언어 한국어 별도 관리, 복습 규칙·기기 저장 안내

일기는 AsyncStorage에 영구 저장되며 앱 재시작 후에도 유지됩니다. 저장 필드는 `id`, `learningLanguage` (`en`/`ja`), `content` (원문), `createdAt`, `updatedAt`, `diaryDate`입니다. 생성·수정 시각은 ISO 형식이고 일기 날짜는 현지 달력 날짜 `YYYY-MM-DD`입니다. 샘플 구분용 `sample` 필드도 사용합니다. 수정 시 id·생성 시각·일기 날짜는 유지하고 수정일만 갱신합니다.

기존 저장 데이터가 없는 첫 실행에는 샘플 일기 2개를 표시합니다. 이후 저장·수정·삭제 시 현재 목록을 저장하며, 일기를 모두 삭제한 경우 다음 실행에서도 빈 목록을 유지합니다. 이전 단계에서 메모리로만 작성한 일기는 영구 저장 데이터로 이전할 수 없습니다.

AsyncStorage 설치는 완료되어 있습니다. 새 환경에서 SDK에 맞춰 추가하는 명령은 아래와 같습니다.

```sh
npx expo install @react-native-async-storage/async-storage
```

SDK 57의 Expo Go에서 지원하는 패키지입니다. 기존 development build를 사용하는 경우 새 네이티브 패키지를 포함하도록 다시 빌드해야 합니다. 웹에서는 같은 브라우저와 사이트 주소의 로컬 저장소를 사용합니다. 로그인, 서버, AI API와 소셜 기능은 연결하지 않았습니다.

## 검증

```sh
npx expo lint
npx tsc --noEmit
npm run test:storage
npx expo export --platform web
```

새 경로를 추가한 뒤에는 `npx expo start`로 Expo Router의 자동 생성 타입을 갱신하세요.

확인할 항목:

1. 하단 탭 네 개와 홈의 질문 및 샘플 일기가 표시되는지 확인합니다.
2. 빈 내용과 공백만 입력했을 때 저장 버튼이 비활성화되는지 확인합니다.
3. 여러 줄 영어 일기를 저장하면 상세에서 줄바꿈과 전체 내용이 유지되는지 확인합니다.
4. 목록과 홈에 새 일기가 맨 위에 나타나고, 탭 이동 후에도 유지되는지 확인합니다.
5. 앱 완전 종료 후 재실행하거나 웹을 새로고침했을 때 작성한 일기가 유지되는지 확인합니다.
6. 단어장의 뜻·예문과 설정의 언어 표시를 확인합니다.
7. iOS / Android의 작은 화면에서 키보드, 스크롤, 뒤로가기를 확인합니다.
8. 상세에서 일기를 수정해 저장한 뒤 홈·목록·상세에 반영되고 재실행 후에도 유지되는지 확인합니다. 생성일은 유지하고 수정일을 표시합니다.
9. 삭제 확인창에서 취소하면 유지되는지, 삭제하면 목록과 홈에서 사라지고 재실행 후에도 나타나지 않는지 확인합니다. 모든 일기를 삭제해도 샘플이 다시 생성되지 않아야 합니다.
10. 로딩 중에는 저장 버튼이 비활성화되어야 합니다. 읽기 오류가 발생하면 기존 저장 데이터를 덮어쓰지 않고 다시 불러오기 버튼을 제공합니다.

저장 실패 검증은 `npm run test:storage`에서 읽기·쓰기 실패를 주입해 자동 확인합니다. 저장소 데이터 손상, 읽기 전 쓰기 차단, 수정·삭제 실패 시 이전 데이터 보존과 재시도를 검증합니다. 화면의 실패 동작을 수동 확인하려면 **테스트용 환경**에서 `local-diary-repository.ts`의 `setItem` 어댑터를 일시적으로 거절하도록 바꾸고 저장해 보세요. 작성·수정 내용과 오류 안내가 유지되어야 합니다. 확인 후 반드시 어댑터를 복원하세요.

화면에는 AsyncStorage 호출을 넣지 않습니다. 저장소의 `load/create/update/remove` 인터페이스로 분리했으며, 쓰기를 순서대로 처리하고 디스크 쓰기에 성공한 뒤에만 공용 상태를 갱신합니다. 초기 읽기 실패나 올바르지 않은 저장 데이터는 빈 목록으로 대체하지 않아 원본이 보존됩니다. 저장 데이터에는 버전 정보를 포함해 이후 마이그레이션이나 서버 동기화를 추가할 수 있습니다.

## 샘플 교정 → 표현 저장 → 단어장

새 패키지 설치는 필요하지 않습니다. 기존 AsyncStorage를 사용하며, 로그인·서버·실제 AI API는 연결하지 않았습니다. 복습은 아래의 간단한 일정 규칙을 사용합니다.

교정은 `CorrectionService.correct(entry)` 인터페이스와 별도 샘플 모듈로 구성됩니다. 향후 실제 API 어댑터를 구현하고 `src/correction/index.ts`에서 구현을 교체할 수 있습니다. 현재 결과는 원본 샘플 ID, 학습 언어, `sample` 표시, 전체 원문이 일치할 때만 제공합니다. 사용자 일기에 샘플과 같은 글을 복사해도 교정 결과가 붙지 않으며, 샘플을 수정하면 지원 안내를 표시합니다.

기존 샘플 두 개는 문법 오류가 없으므로 문법 오류 수정은 0개로 표시하고, 원문을 그대로 유지한 채 자연스러운 대안 표현을 제공합니다. 단어·표현·문법은 **저장 항목 유형**이며, 문법 유형의 항목도 문법 오류가 아닌 대안 문장 구성 학습일 수 있습니다. 모든 결과에 샘플 교정임을 표시합니다.

학습 항목은 `@lingolog/learning-items/v1`에 일기와 별도로 저장합니다. 유형, 표현, 한국어 뜻 또는 설명, 원래 문장, 교정된 예문, 학습 언어, 원본 일기 ID, 교정 항목 ID, 저장일을 보관합니다. 예문은 저장 당시 내용의 복사본이므로 원본 일기를 수정·삭제해도 유지됩니다. 일기와 학습 항목 삭제는 서로 영향을 주지 않습니다.

같은 학습 언어·유형·표현은 한 번만 저장하며, 대소문자와 연속 공백 차이도 중복으로 처리합니다. 여러 일기에서 같은 항목을 저장하면 처음 저장한 예문과 출처를 유지합니다. 저장한 항목을 단어장에서 삭제하면 교정 화면에서 다시 저장할 수 있습니다. 단어장 읽기 전에는 저장을 막고, 실패하면 기존 데이터와 교정 결과를 유지한 채 오류와 재시도를 제공합니다.

확인 순서:

1. 원문이 그대로인 샘플 일기 상세에서 **교정하기**를 누릅니다. **샘플 교정 · 실제 AI 결과가 아닙니다** 표시, 원문·교정문, 문법/자연스러운 표현 구분, 한국어 변경 이유를 확인합니다.
2. 첫 번째 샘플에서 `go for a walk`(표현), `thankful`(단어)을 저장합니다. 두 번째 샘플에서 `Although + 주어 + 동사`(문법)를 저장합니다.
3. 저장 버튼이 **단어장에 저장됨**으로 바뀌고 다시 눌러도 목록 항목 수가 증가하지 않는지 확인합니다.
4. 단어장 탭과 상세에서 유형·뜻/설명·원래 문장·교정 예문·영어·원본 링크를 확인합니다. 앱을 완전히 종료한 뒤 재실행해도 항목이 유지되어야 합니다.
5. 원본 일기를 삭제하고 학습 항목 상세를 다시 엽니다. 출처가 삭제되었다는 안내와 저장된 예문이 유지되는지 확인합니다.
6. 학습 항목 삭제 확인창에서 취소하면 유지되고, 삭제하면 재실행 후에도 사라지는지 확인합니다. 학습 항목을 삭제해도 원본 일기는 유지되어야 합니다.
7. 직접 쓴 일기 또는 수정한 샘플에서 교정하기를 누르면 지원 안내만 나오고, 무관한 교정문이나 저장 버튼이 나오지 않는지 확인합니다.

샘플을 이미 수정하거나 삭제했다면 **일기 탭 → 교정용 샘플 일기 추가**를 누르세요. 교정 가능한 샘플만 추가하며, 기존 일기와 단어장 데이터는 유지합니다. 이미 교정 가능한 샘플이 있으면 중복 추가하지 않습니다. 수정된 샘플이 같은 ID를 사용 중이면 별도 ID로 새 샘플을 추가하므로 수정한 내용과 기존 학습 항목의 출처가 유지됩니다. 새 샘플도 기기에 저장되어 재실행 후 유지됩니다.

`npm run test:storage`에는 기존 일기 테스트와 함께 샘플 매칭, 유형 구분, 중복 저장, 재시작 복원, 원본 수정·삭제 후 예문 유지, 단어장 읽기·쓰기 실패 및 재시도 테스트가 포함됩니다.

## 저장한 표현으로 오늘 복습

단어장 또는 홈의 **오늘 복습**에서 선택한 학습 언어의 미복습·기한 도래·기한 지난 항목만 복습합니다. 앞면에는 한국어 뜻이나 설명만 나오며, **답 보기**를 누르기 전에는 표현·예문·자기평가 버튼을 렌더링하지 않습니다. 뒷면에는 학습 언어의 표현, 저장한 일기의 교정된 예문과 원래 문장이 나옵니다.

자기평가 규칙:

- **다시 연습**: 연속 기억 횟수를 0으로 초기화하고 오늘 일정에 남깁니다. 현재 세션 뒤쪽에서 한 번 더 보여줍니다. 반복 카드에서 다시 연습을 선택하면 세션은 끝낼 수 있고, 해당 항목은 다음 세션에서 계속 복습합니다. 카드가 하나뿐인 경우 다음 카드가 같은 항목입니다.
- **기억했어요**: 연속 횟수에 따라 1·3·7·14·30일 뒤를 다음 날짜로 지정하고 이후에는 30일 간격을 유지합니다. 날짜는 기기의 현지 달력 날짜이며, 월말·연말·윤년을 처리합니다.
- 저장에 성공한 평가만 기록하고 다음 카드로 이동합니다. 실패하면 답을 보여준 현재 카드를 유지하고 재시도를 제공합니다. 답을 보기 전에는 세션 로직에서도 평가를 차단합니다.

자동 채점은 하지 않습니다. 이력에는 `evaluationSource: self`, `selfRating: again | remembered`, `automaticGrade: null`을 저장합니다. 홈과 단어장에는 오늘 복습 대상 수, 오늘 복습한 고유 항목 수, 누적 자기평가 횟수를 표시합니다. 정답률·자동 점수로 표현하지 않습니다. 같은 항목을 반복 평가하면 이력 횟수는 늘어나지만 오늘 복습한 항목 수는 한 개로 계산합니다.

저장 분리:

| 데이터 | 저장 키 | 내용 |
| --- | --- | --- |
| 학습 항목 | `@lingolog/learning-items/v1` | 표현·뜻·예문·언어·출처 (JSON 스키마 버전 2) |
| 복습 상태·이력 | `@lingolog/review/v1` | `states` 일정과 `history` 자기평가를 별도 컬렉션으로 관리 |
| 언어 설정 | `@lingolog/preferences/v1` | `learningLanguage`와 `explanationLanguage` |

복습 상태와 이력은 학습 항목을 수정하지 않으며, 같은 저장 작업에서 함께 기록하여 일정만 저장되고 이력이 누락되는 상황을 막습니다. 학습 항목을 삭제하면 오늘 복습 대상에서 빠지지만 기존 복습 이력은 유지하고 삭제된 항목이라고 표시합니다. 앱을 종료하면 진행 중인 카드 순서는 끝나지만 저장한 평가·일정은 유지하며, 다시 연습한 항목은 다음 실행에서도 오늘 복습 대상입니다.

기존 버전 1 학습 데이터는 기존 저장 키에서 그대로 읽고, 누락된 설명 언어는 `ko`, 누락된 학습 언어는 `en`으로 처리합니다. ID·예문·뜻·출처·저장일을 유지하며 읽는 과정에서는 데이터를 쓰지 않습니다. 다음 명시적 저장·삭제 성공 시 버전 2로 기록합니다. 복습 상태가 없는 기존 항목은 오늘 복습할 새 항목으로 취급하므로 초기 빈 상태로 학습 데이터를 덮어쓰지 않습니다. 잘못된 JSON이나 지원하지 않는 버전은 기존 바이트를 보존하고 오류·재시도를 제공합니다.

영어와 일본어는 학습 언어로 구분되며 설명 언어는 현재 한국어를 지원합니다. 설정 또는 홈·단어장 언어 선택을 바꾸어도 기존 항목의 언어는 바뀌지 않습니다. 일본어 일기 저장과 복습 데이터 구조는 준비되어 있지만 일본어 교정·표현 추출은 아직 제공하지 않아 일반 사용 흐름에서 새 일본어 학습 항목은 생성되지 않습니다. 실제 AI API·음성 인식·소셜 기능은 추가하지 않았습니다. 추가 패키지 설치도 필요하지 않습니다.

복습 확인 순서:

1. 기존 영어 항목이 유지되는지 확인합니다. 항목이 없다면 일기 탭의 **교정용 샘플 일기 추가 → 교정하기 → 단어장에 저장**으로 2개 이상의 항목을 준비합니다.
2. 영어를 선택하고 홈과 단어장의 오늘 복습 수가 일치하는지 확인합니다. **오늘 복습**에 들어가서 뜻만 보이고 정답·예문·평가 버튼이 숨겨져 있는지 확인합니다.
3. **답 보기 → 다시 연습**을 누릅니다. 다른 카드 뒤에서 해당 항목이 다시 등장하고, 다시 등장했을 때도 답이 숨겨져 있어야 합니다.
4. **답 보기 → 기억했어요**를 누릅니다. 다음 날짜 안내와 학습 항목 상세의 다음 복습일을 확인합니다. 첫 기억 평가는 다음 날로 예약되어 오늘 복습 수에서 빠집니다.
5. 복습 이력에서 **자기평가** 표시와 두 종류의 기록을 확인합니다. 앱 완전 종료 후 재실행해도 이력·다음 날짜·오늘 복습 수가 유지되는지 확인합니다.
6. 일본어로 바꾸면 영어 항목과 영어 통계가 섞이지 않아야 합니다. 영어로 돌아오면 기존 항목·일정·통계가 그대로 나타나야 합니다. 설명 언어는 계속 한국어입니다.
7. 일본어 일기를 저장하고 재실행해 학습 언어가 유지되는지 확인합니다. 교정하기에서는 아직 지원하지 않는다는 안내만 표시되어야 합니다.
8. 기존 학습 항목을 삭제하면 해당 카드가 복습 대상에서 빠지고, 원본 일기 삭제는 저장한 학습 항목·복습 일정에 영향을 주지 않는지 확인합니다.

`npm run test:storage`는 기존 기능과 함께 데이터 이전, 정답 공개 전 평가 차단, 세션 후반 반복·종료, 날짜 계산, 언어별 통계, 자기평가 저장·재시도·중복 방지, 재실행 복원, 언어 설정과 일본어 일기 저장을 검증합니다. 화면의 저장 실패는 테스트용 환경에서 복습 저장소의 `setItem`을 일시적으로 실패시키고 확인할 수 있습니다. 확인 후 반드시 복원하세요.

## 텍스트 읽어주기 (TTS)

Expo SDK 57에 맞춰 `npx expo install expo-speech`로 `expo-speech ~57.0.3`을 설치했습니다. 다른 환경에서 프로젝트를 받으면 `npm install` 후 `npx expo start --clear`로 실행합니다. PowerShell 실행 정책 때문에 명령이 막히면 `npm.cmd`, `npx.cmd`를 사용하세요. `expo-speech`는 SDK 57 Expo Go에 포함됩니다. 기존 개발 빌드를 사용하는 경우 새 네이티브 패키지를 포함하도록 개발 빌드를 다시 만들어야 합니다.

일기 상세와 샘플 교정 화면에서 원문·교정문 전체 듣기 및 문장별 듣기를 제공합니다. 일기 상세의 교정문은 원문이 일치하는 샘플에만 표시되며 일반 일기나 수정한 샘플에는 원문 듣기만 표시됩니다. 단어장 목록·상세에는 표현과 저장 당시 교정된 예문 듣기가 있고, 복습 카드의 음성 버튼은 **답 보기** 이후에만 나타납니다.

`src/speech/speech-controller.ts`는 언어 설정·긴 글 분할·기기 음성 확인·재생 교체·오류 처리를 관리합니다. `src/state/speech-context.tsx`는 단일 재생 컨트롤러와 화면 이동/AppState 중지 처리를 제공합니다. `SpeechControls`는 공통 UI입니다. 영어는 `en-US`, 일본어는 `ja-JP` 음성을 우선 선택하고, 해당 지역 음성이 없으면 같은 언어의 다른 지역 음성을 사용합니다. 다른 언어 음성으로 대체하지 않습니다. 기본 속도 1.0 / 느린 속도 0.7 선택은 언어별로 분리하고 실행 중 메모리에서 유지합니다. 앱 재시작 시 속도는 기본으로 돌아옵니다. 음성·속도 변경은 기존 저장 데이터와 무관합니다.

기기 내 TTS 엔진을 사용하며 외부 유료 TTS API·녹음·발음 평가는 추가하지 않았습니다. 실제 음색·속도·네트워크 필요 여부는 설치된 기기 음성 및 TTS 엔진에 따라 다릅니다. 언어 음성이 없거나 재생 준비/재생이 실패하면 화면에 안내합니다. iPhone 무음 모드에서는 소리가 나지 않을 수 있으며, 무음 여부를 앱에서 감지해 오류로 판단하지는 않습니다. [Expo SDK 57 Speech 문서](https://docs.expo.dev/versions/v57.0.0/sdk/speech/)

실제 iPhone과 Android 확인 순서:

1. 기존 일기·단어장·복습 기록이 유지되는지 확인합니다. 샘플 일기가 없다면 일기 탭에서 **교정용 샘플 일기 추가**를 누릅니다.
2. 샘플 일기 상세에서 원문 전체 / 샘플 교정문 전체를 각각 재생하고, 문장별 듣기를 펼쳐 선택한 문장만 들리는지 확인합니다. 직접 작성하거나 수정한 샘플에는 무관한 교정문 버튼이 없어야 합니다.
3. 긴 영어 일기와 일본어 일기를 재생하고 마지막까지 읽는지 확인합니다. 영어·일본어가 각 언어 음성으로 읽히고, 기본/느린 속도 차이가 있는지 확인합니다.
4. 재생 중 중지 버튼을 눌러 즉시 멈추는지 확인합니다. 빠르게 다른 문장·원문/교정문·표현/예문을 선택해도 겹치거나 이전 글이 뒤늦게 재생되지 않아야 합니다.
5. 단어장 목록과 상세에서 표현·예문을 들어봅니다. 복습 앞면에는 정답 음성 버튼이 없고, **답 보기** 후에만 나타나야 합니다. 자기평가 후 다음 카드로 넘어가면 이전 음성이 멈추어야 합니다.
6. 재생 중 탭 이동, 상세 뒤로가기, 일기 수정 진입, 앱 홈 이동, 화면 잠금을 각각 확인합니다. 돌아와도 자동으로 재생을 다시 시작하지 않아야 합니다.
7. iPhone은 무음 모드를 해제하고 기기 음량을 올려 테스트합니다. Android는 미디어 음량과 시스템 텍스트 읽어주기 엔진·언어 음성 설치 여부를 확인합니다. 기기에 영어/일본어 음성이 없는 상황에서는 안내가 나오고 다른 언어로 읽지 않아야 합니다. 음성을 설치한 뒤 다시 눌러 재시도합니다.
8. 앱을 완전히 종료하고 다시 열어 일기·학습 항목·복습 기록이 그대로인지 확인합니다. 일본어의 실제 교정 지원은 이번 단계에 추가하지 않았습니다.

`npm run test:speech`는 7개 테스트로 문장 분리, 길이 제한·유니코드 보존, 언어·속도 선택, 빠른 재생 교체, 대기 중 취소, 음성 누락, 동기/비동기 재생 오류를 검증합니다. 실제 스피커 출력 및 운영체제 음성 엔진 동작은 위 실기기 절차로 확인해야 합니다.

## 기록이 머무는 집 · 영어 / 뉴욕

아래는 첫 버전의 구현 기록입니다. 현재 화면과 날짜 처리 기준은 다음의 **뉴욕·도쿄와 월간 달력** 절을 참고하세요.

홈의 영어 집은 누적 **작성일**에 따라 0일(빈 대지) → 1일(기초) → 3일(벽과 지붕) → 5일(완성된 집) → 7일(꾸며진 집)로 성장합니다. 같은 언어·같은 현지 날짜에 여러 편을 저장해도 한 번만 계산합니다. 연속 출석, 언어 실력 점수, 복습 정답률과 관계없으며 쉬거나 일기를 삭제해도 기록과 보상은 줄지 않습니다. 복습 횟수 자체는 이번 단계의 집 성장 조건이 아닙니다.

새 일기를 성공적으로 저장할 때만 작성일이 생성됩니다. 수정·샘플 추가/수정·실패한 저장은 새 보상을 만들지 않습니다. 기존 사용자 일기는 학습 언어별 고유 **생성일**을 한 번 반영하며, 샘플 출처가 남은 일기는 제외합니다. 새 작성일은 저장 당시 현지 날짜를 고정해 두고, UTC 날짜 문자열을 잘라서 계산하지 않습니다. 기존 일기에 현지 날짜/시간대 필드가 없으므로 최초 이전 시 기기 시간대에서 생성 시각을 해석합니다. 이전 완료 후에는 시간대를 바꿔도 기존 날짜를 다시 해석하지 않습니다.

보상은 `@lingolog/growth/v1`의 `days`(언어·날짜)와 `migrated`(최초 이전 완료)로 영구 저장합니다. 기존 일기·학습 항목·복습 저장 키는 유지합니다. 일기 저장 객체에는 일기와 함께 원자적으로 저장하는 `writingDays` 전달 기록을 추가했습니다. 이 기록은 삭제해도 남고, 보상 저장소가 실패한 뒤 재실행해도 재처리할 수 있습니다. `source: legacy`인 이전 후보는 최초 이전에만 사용합니다. 별도 보상 저장 실패가 성공한 일기 저장을 취소하지 않으며, 홈/일기 작성/상세의 **작성일 보상 다시 반영**으로 재시도할 수 있습니다. 언어·날짜 키로 합치므로 재시도와 동시 처리도 중복 지급되지 않습니다. 잘못된 JSON·지원하지 않는 버전은 덮어쓰지 않고 안내합니다.

`src/growth/`는 성장 규칙과 저장소, `GrowthProvider`는 일기 저장 결과 반영을 관리합니다. `HouseGraphic`은 진행 단계와 테마만 받는 프로젝트 내 View 그래픽이며 나중에 이미지로 교체할 수 있습니다. `src/data/city-themes.ts`는 학습 언어와 별개로 도시 ID를 관리하고, 보상에는 테마 ID를 쓰지 않습니다. 이번 UI에는 영어·뉴욕만 있으며 런던·도쿄 선택지는 아직 제공하지 않습니다. 일본어 일기·복습과 언어별 작성일은 유지되지만 일본어 집과 실제 교정은 지원한다고 표시하지 않습니다.

오늘의 영어 질문은 `src/data/writing-questions.ts`의 세 유형(오늘 있었던 일 / 상상하기 / 한 문장 쓰기)을 사용합니다. 기기 현지 날짜에 따라 기본 질문이 결정되어 같은 날 다시 실행해도 같습니다. **다른 질문 보기**로 로컬 질문을 순환합니다. 대체 질문 선택은 현재 홈 화면에서 유지하며 재실행하면 그날의 기본 질문으로 돌아옵니다. **일기 쓰기**는 질문 ID만 Expo Router로 전달해 질문 영역에 표시합니다. 본문을 자동으로 채우거나 지우지 않습니다. 작성 중인 내용과 작성 언어는 유지하고, 빈 작성 화면에서 영어 질문을 열면 영어로 작성합니다. **홈 질문 닫기**로 기존 언어 선택 흐름으로 돌아갈 수 있습니다.

기존 데이터 반영과 앱 시작 시 누적 상태 복원은 조용히 수행합니다. 실행 중 새로운 영어 성장 단계에 도달하면 한 번의 짧은 축하창을 표시합니다. 여러 단계가 한꺼번에 반영되어도 축하창을 연속으로 띄우지 않습니다. 홈은 스크롤 가능한 세로 배치, 줄바꿈되는 지표와 전체 너비 버튼을 사용하며, 큰 글자를 강제로 축소하거나 주요 버튼 높이를 고정하지 않습니다. 추가 패키지는 필요 없습니다.

실제 기기 확인:

1. 업데이트 전 사용하던 앱 데이터 그대로 실행합니다. 기존 일기·단어장·복습 이력·TTS가 유지되고, 영어 사용자 일기의 고유 작성일만 집에 반영되는지 확인합니다. 첫 실행에서 축하창이 연속으로 나타나지 않아야 합니다.
2. 빈 글/공백 저장은 막히고, 새 영어 일기를 저장하면 해당 현지 날짜의 작성일이 한 번 추가되어야 합니다. 같은 날 두 번째 저장과 기존 일기 수정은 추가 보상을 만들지 않아야 합니다.
3. 획득한 날의 일기를 삭제하고 앱을 완전히 종료·재실행합니다. 집 단계와 누적 작성일이 유지되어야 합니다. 샘플 추가·샘플 수정은 보상에 포함되지 않아야 합니다.
4. 테스트용 별도 데이터나 서로 다른 실제 작성일로 0/1/3/5/7일 경계를 확인합니다. 집 그래픽·단계·다음 보상까지 남은 날이 일치하고, 7일 이후에도 작성일은 계속 쌓여야 합니다. 기기를 쉬었다 사용해도 감소/결석 경고가 없어야 합니다. 실제 사용자 저장소를 초기화하지 마세요.
5. 홈의 질문 유형과 **다른 질문 보기**를 확인합니다. 선택한 질문으로 **일기 쓰기**를 누르면 해당 질문이 표시되어야 합니다. 미리 입력한 내용이 있을 때 홈으로 갔다 돌아와도 글과 작성 언어가 바뀌지 않아야 합니다. 같은 날 재실행 시 그날의 기본 질문이 같아야 합니다.
6. 일본어를 선택해 기존 일기와 복습을 확인합니다. 영어 집은 영어 기록만 보여 주고 일본어 집은 준비 중으로 안내해야 합니다. 영어로 돌아오면 기존 진행도가 그대로여야 합니다.
7. 홈의 오늘 복습 수와 **복습하기**, 일기·단어장·설정 이동, 상세 뒤로가기와 TTS 중지를 확인합니다.
8. 작은 iPhone/Android 화면과 큰 글자 설정에서 집·단계 설명·쓰기/복습/재시도/축하창 닫기 버튼을 스크롤해 모두 누를 수 있는지 확인합니다.
9. 저장 실패 확인은 별도 테스트 환경에서 AsyncStorage `setItem`이 `@lingolog/growth/v1`에만 실패하도록 설정합니다. 일기는 저장되고 안내가 나타나야 합니다. 실패 중 해당 일기를 삭제·재실행한 뒤 실패 설정을 복원하고 재시도해도 작성일은 정확히 한 번 반영되어야 합니다. 원본 사용자 데이터는 보존하세요.

`npm run test:growth`는 성장 경계·언어별 계산·샘플 제외·안전한 이전·작성일 전달 기록·실패/삭제/재실행 재처리·중복 방지·시간대·질문·미지원 테마를 검증합니다. 실행은 기존과 동일하게 `npx.cmd expo start --clear`입니다.

## 뉴욕·도쿄와 월간 달력

홈은 언어 선택, 선택한 언어의 집과 짧은 성장 진행, 오늘의 질문과 쓰기 버튼만 표시합니다. 성장 규칙은 **자세히**를 눌러 확인합니다. 최근 일기·복습·상세 통계는 홈에서 제거했으며 복습과 통계는 단어장에서 계속 이용할 수 있습니다. 언어 선택은 기존 AsyncStorage 설정을 재사용해 재실행 후에도 유지합니다.

영어는 뉴욕, 일본어는 도쿄를 사용합니다. 공통 `HouseGraphic`의 구도·단계를 유지하면서 도쿄에는 낮은 골목 배경, 타워, 처마·창살·등불·벚꽃 장식을 추가했습니다. 성장·보상 키는 테마와 독립적인 언어·실제 작성일이므로 언어별 기록이 섞이지 않습니다. 일본어 질문은 한국어로 안내하고 같은 날의 기본 질문은 고정됩니다. 일본어 저장·상세·TTS는 기존 기능을 재사용하며, 일본어 교정은 명확히 **미지원**으로 안내합니다. 영어 샘플 교정과 샘플 추가는 유지하며 샘플 추가 버튼은 설정으로 옮겼습니다.

일기 탭은 월간 달력입니다. **이전 달 / 다음 달 / 오늘**을 제공하고, 선택한 언어의 기록이 있는 날은 **•**, 선택한 날은 테두리와 **✓**로 표시합니다. 날짜를 누르면 해당 날짜의 모든 일기를 달력 아래 카드로 확인하며 기존 상세 화면으로 이동합니다. 전체 목록을 기본 화면에 표시하지 않습니다. 미래 날짜는 조회할 수 있지만 쓰기 버튼은 비활성화하며 저장소에서도 미래 날짜를 거부합니다. 큰 글자에서는 날짜를 줄이거나 잘라내지 않고 필요한 경우 달력을 가로로 스크롤합니다.

날짜 역할:

| 필드 | 용도 |
| --- | --- |
| `createdAt` | 실제 저장한 시각; 집 보상은 이 시각의 현지 작성일 기준 |
| `updatedAt` | 마지막 수정 시각 |
| `diaryDate` | 일기를 배치할 달력 날짜; 과거 날짜 작성 가능, 수정 시 유지 |

`src/dates/local-date.ts`에 현지 날짜, 검증, 월간 배열·월 이동·날짜 표시 로직을 모았습니다. 복습의 기존 날짜 함수는 이 공통 모듈을 재사용합니다. 달력 필터·개수는 `src/data/diary-calendar.ts`에서 관리합니다. 과거 날짜에 여러 편을 저장해도 보상은 실제 저장한 날에 언어별 한 번만 쌓입니다. 이미 지급한 보상과 일기 삭제 후 재시도용 작성일 기록도 유지합니다.

기존 일기 저장 키 `@lingolog/diaries/v1`은 그대로 두고 JSON 스키마를 버전 2로 이전합니다. 버전 1을 읽을 때 생성 시각을 **이전 당시 기기의 현지 날짜**로 해석해 `diaryDate`를 붙이고, 기존 일기와 작성일 전달 기록을 함께 저장한 뒤 화면에 노출합니다. 이후에는 저장된 일기 날짜를 사용하므로 시간대 변경으로 달력 날짜가 이동하지 않습니다. 초기 빈 데이터로 덮어쓰지 않고, 읽기·검증·이전 저장에 실패하면 원본을 유지한 채 재시도를 제공합니다. 일기 ID·본문·언어·생성/수정 시각·샘플 정보·보상 기록을 유지하고 학습 항목·복습·언어 설정 키는 초기화하지 않습니다. 최초 설치의 기본 샘플은 사용자 저장이 없는 예시 데이터로 유지합니다.

홈은 언어·오늘 날짜·선택한 질문 ID를, 달력은 언어·선택한 일기 날짜를 `/diary/write`에 전달합니다. 작성 화면은 언어와 날짜를 표시합니다. 전역 메모리의 작성 초안이 비어 있지 않으면 새 요청으로 본문·언어·날짜·질문을 바꾸지 않고 기존 글을 이어 엽니다. 저장 실패 시 내용도 유지합니다. 초안은 이번 단계에서 기기 영구 저장 대상은 아니며, 앱 프로세스를 종료하면 입력 중인 내용은 사라집니다. 저장된 일기는 영구 유지합니다.

실제 기기 확인:

1. 기존 데이터가 있는 앱을 그대로 업데이트해 일기·단어장·복습·보상 기록이 유지되는지 확인합니다. 언어 선택을 일본어로 바꾸고 완전 종료·재실행해 선택이 유지되는지 확인합니다.
2. 홈이 언어 선택·집·진행·질문·쓰기만 표시하는지, 뉴욕/도쿄 집과 성장 기록이 각각 맞는지 확인합니다. 자세히와 축하창은 큰 글자에서도 닫을 수 있어야 합니다.
3. 달력의 월 이동·오늘 이동을 확인합니다. 기록 점·선택 테두리/체크가 보이고, 같은 날짜의 여러 편이 모두 나타나며 영어·일본어 기록이 섞이지 않아야 합니다.
4. 오늘/과거 날짜의 쓰기로 진입해 언어·일기 날짜가 전달되는지 확인합니다. 저장한 과거 일기는 선택한 날짜에 나타나고, 수정·재실행 후에도 그 자리에 있어야 합니다. 미래 날짜는 쓰기와 저장이 막혀야 합니다.
5. 같은 실제 날짜에 여러 과거 날짜로 저장해도 해당 언어의 작성일 보상은 한 번만 늘어야 합니다. 일기 삭제·재실행 후에도 보상은 유지되어야 합니다.
6. 일본어 홈 질문이 한국어로 안내되고 작성 화면에도 전달되는지 확인합니다. 일본어 글을 저장해 상세에서 일본어 음성으로 듣고, 교정하기에서는 미지원 안내가 나오는지 확인합니다. 영어 샘플 교정은 계속 이용할 수 있어야 합니다.
7. 글을 입력하다 뒤로가기 후 다른 언어/날짜/질문으로 쓰기를 누릅니다. 기존 본문·언어·날짜가 유지되고 안내가 나와야 합니다. 저장한 뒤에는 다음 새 요청으로 작성할 수 있어야 합니다.
8. 작은 화면과 큰 글자 설정에서 달력 날짜·선택 표시·월 이동 버튼·쓰기/저장 버튼이 접근 가능한지 확인합니다. 가로로 커진 달력은 스크롤해 일~토 전체를 확인합니다.
9. 별도 테스트 환경에서 일기 스키마 이전 저장만 실패시켜 원본이 유지되는지, 재시도 후 정상 이전되는지 확인합니다. 실제 사용자 데이터는 초기화하지 마세요.

추가 패키지는 없습니다. `npm run test:calendar`는 10개 테스트로 안전한 날짜 이전·실패 복구·과거 작성과 실제 작성일 보상·미래 차단·언어별 달력·윤년/월 이동·시간대·초안 보호·일본어 질문과 미지원 교정을 검증합니다. 기존 저장·성장·TTS 테스트도 함께 유지합니다.
